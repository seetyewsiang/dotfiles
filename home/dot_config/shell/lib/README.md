# Shell function library

Functions from Dylan Araps' pure sh and pure bash bibles, renamed to one
consistent scheme, split by domain, and written for three shells. Both
repos are MIT licensed; the notices are in `LICENSE-pure`.

- `sh/`: POSIX sh. From <https://github.com/dylanaraps/pure-sh-bible>,
  plus ports of the bash functions.
- `bash/`: bash. From <https://github.com/dylanaraps/pure-bash-bible>,
  plus the sh functions.
- `zsh/`: zsh, written with zsh's own features.

## Use

This is a reference library. Copy the functions you need into your
script so it stays self-contained. Nothing here is sourced from a shell
rc file.

To source a whole domain anyway:

```sh
. ~/.config/shell/lib/sh/str.sh        # from sh, dash or bash
. ~/.config/shell/lib/bash/str.bash    # from bash only
. ~/.config/shell/lib/zsh/str.zsh      # from zsh only
```

The bash files don't work in zsh, nor the zsh files in bash. The sh files
also work in zsh when loaded under sh emulation
(`emulate sh -c '. ~/.config/shell/lib/sh/str.sh'`).

## Naming

Every function is `<domain>_<action>` in lowercase snake_case, so no
name shadows a real command (`file_head`, not `head`).

| File | Prefixes |
|---|---|
| `str` | `str_` |
| `fs` | `file_` `dir_` `path_` `glob_` |
| `num` | `num_` |
| `var` | `var_` |
| `sys` | `sys_` |
| `arr` | `arr_` |
| `color` | `color_` |
| `term` | `term_` |

- Yes/no checks are named `*_is_*`, `*_contains`, `*_starts_with` or
  `*_ends_with`, and only set the exit status.
- "trim" removes whitespace; "strip" removes a pattern.
- A function has the same name and arguments in every shell that has it,
  so a script can switch shells without renaming calls. The files for one
  domain (`sh/str.sh`, `bash/str.bash`, `zsh/str.zsh`) list their
  functions in the same order: first those every shell has, then the rest.
- bash and zsh have every function. sh lacks seven that need arrays or
  shell features POSIX sh doesn't have: `arr_cycle`, `file_read_array`,
  `str_regex`, `term_window_size`, `term_cursor_pos`, `sys_functions` and
  `sys_is_sourced`.

## Notes

- Each function's doc comment uses shdoc tags (`@description`,
  `@example`, `@arg`, `@stdout`, `@exitcode`, `@set`, `@see`). In
  examples, lines starting with `#=>` show the expected output.
- "Source: wrapped from a bible snippet" marks functions made from
  snippets in the bibles; "Source: ported from the bash version" marks sh
  functions written here. The zsh files are all written here.
- "Fix:" in a description marks a small change to upstream code.
- "Requires bash 4+" (or 4.2+, 4.3+, 4.4+) marks functions that fail on
  the bash 3.2 macOS ships; they need a newer bash (`brew install bash`).
- The sh functions use global helper variables, since POSIX sh has no
  `local`. POSIX sh also has no case conversion, randomness or clock, so
  a few sh functions run a standard tool; the table marks them ("uses
  `tr`").
- Each zsh function starts with `emulate -L zsh` and declares its
  variables `local`, so it behaves the same whatever options your shell
  has set.
- Reference sections of the bibles with no code to wrap (escape
  sequences, parameter expansion, operators, traps, obsolete syntax,
  code-golf tips) are left out.

## Regenerating the docs

`docs/` is regenerated automatically by the dotfiles repo's pre-commit
hook (`.githooks/pre-commit`). When a commit changes a file in `sh/`,
`bash/` or `zsh/`, the hook:

1. runs every `@example` (`tools/doctest-shell-lib.py`) and refuses the
   commit if an example's output no longer matches;
2. regenerates `docs/` with shdoc and adds it to the commit.

It needs shdoc and gawk (installed by mise); without them it warns and
lets the commit through. Hooks are enabled per clone by
`git config core.hooksPath .githooks`, which the chezmoi script
`run_once_after_50-git-hooks.sh.tmpl` runs on a new machine.

To regenerate by hand, from the chezmoi source:

```sh
cd "$(chezmoi source-path)/dot_config/shell/lib" && ./executable_gendocs.sh
```

## Known issues

- `sys_sleep` (bash) failed on macOS bash 3.2 with
  `/dev/fd/62: Permission denied` and returned at once instead of
  sleeping.
- `arr_reverse` (bash) reads `BASH_ARGV`, so when called from a file that
  was itself sourced with arguments it prints those arguments too.
